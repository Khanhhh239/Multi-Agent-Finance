# PLAN_08 execution contracts

Generated by `scripts/validate_plan08.py`: ComplianceResult, RuleOutcome, EngineContext, Aggregate, ModelPackage, ExecutionPolicy and PaymentProof.

Use Pydantic domain validation plus `src.rules.replay.verify` for persisted results. JSON Schema alone does not prove tenant ownership, hash bindings, evidence, model approval, raw trace consistency or terminal-attempt selection. HTTP callers cannot submit JDM, facts, package paths or payment proof sidecars.

Money is evaluated with `decimal-facts-v1` before entering ZEN. Engine facts are strict booleans. Successful outcomes require an approved pinned model, context and nonempty raw/normalized trace; execution ERROR has a null tax result. Aggregation contract errors have a null record verdict.

`technical_only=true` distinguishes this implementation from a legal release. Real models remain DRAFT. See [runbook](../../../docs/agent3/plans/evidence/plan08/runbook.md) and [gate](../../../docs/agent3/plans/evidence/gate_08.md).
