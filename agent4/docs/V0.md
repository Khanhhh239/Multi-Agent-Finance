# V0 — Baseline Governed Text-to-Metrics-to-SQL Architecture & Implementation Plan

> **Trạng thái:** V0 Baseline Specification  
> **Mục tiêu:** Xây dựng phiên bản đầu tiên (End-to-End Proof of Concept) kiểm tra tính trơn tru, đúng đắn và an toàn của toàn bộ luồng nghiệp vụ governed Text-to-Metrics-to-SQL trước khi tối ưu hóa sâu.

---

## 1. Tầm nhìn & Mục tiêu của V0

V0 là phiên bản nền móng của trợ lý phân tích tài chính thông minh (**Financial Analytics Assistant**). Hệ thống hoạt động theo nguyên tắc **governed text-to-metrics-to-SQL assistant**, không phải một chatbot sinh SQL tự do:
1. **Kiểm tra tính trơn tru End-to-End**: Đảm bảo một câu hỏi từ người dùng (tiếng Việt hoặc tiếng Anh) đi qua toàn bộ pipeline 9 chốt chặn (validation gates), truy vấn dữ liệu từ kho tài chính DuckDB thật và trả về câu trả lời có bằng chứng (provenance), không bịa đặt số liệu (zero hallucination).
2. **Đánh giá chuẩn qua Benchmark**: Đo lường độ chính xác ngay từ đầu bằng bộ benchmark 120 câu hỏi đã xây dựng (`data/eval/contract_benchmark_questions.jsonl`) bao phủ 8 nhóm nghiệp vụ và kiểm định trên cơ sở dữ liệu `cfo_warehouse.duckdb`.
3. **Tuân thủ tuyệt đối Contract & Scope**: Mọi module giao tiếp qua typed contracts đã định nghĩa trong `contracts.md`, bảo đảm ranh giới an toàn (trust boundaries) quy định trong `scope.md`.

## 2. Kiến trúc Pipeline Chuẩn của V0

```text
[1. User Query Intake] (Chuẩn hóa câu hỏi, kiểm tra locale vi-VN/en-US, chặn unknown fields)
       │
       ▼
[2. Metric Retrieval & Fusion]
   ├── Dense Retrieval (Vector query embedding)
   ├── Lexical Retrieval (BM25 / Keyword matching trên alias/label)
   └── Reciprocal Rank Fusion (RRF) & Reranking ──► MetricCandidateSet
       │
       ▼
[3. Dynamic Few-shot Retrieval] (Lọc ví dụ tương thích compatible_only: expected ⊆ candidates)
       │
       ▼
[4. LLM Metric Selection] (Model cục bộ: Sài qwen 4b đang có sẵn)
       │
       ▼
[5. Metrics Validation] ◄── [AUTHORITY CUỐI CÙNG CHO METRIC]
   ├── Kiểm tra subset: selected_metric_ids ⊆ candidates ⊆ approved_catalog
   ├── Kiểm tra quyền truy cập View (mgmt / tax / gl) & allowed_metrics
   └── Kiểm tra tính tương thích period_type (không mix flow với snapshot)
       │
       ▼
[6. Query Planning & Plan Validation]
   ├── Planner sinh SemanticPlanDraft (time, dimensions, filters, view, operation, top_k)
   ├── Xử lý câu hỏi mơ hồ: Trả về trạng thái `needs_clarification` (không tự ý đoán)
   └── Plan Validator thẩm định ranh giới: date range, allowlist dimensions/filters ──► ValidatedPlan
       │
       ▼
[7. SQL Compilation & Safety Gate]
   ├── SQL Compiler: Biên dịch từ ValidatedPlan (chỉ SELECT/CTE, parameterized, row_cap)
   └── SQL Safety Validator: Chặn DML/DDL, đa lệnh (;), relation lạ, literal injection ──► SafeBoundQuery
       │
       ▼
[8. Read-only SQL Execution] (Thực thi an toàn trên DuckDB cfo_warehouse.duckdb, timeout limit)
       │
       ▼
[9. Result Validation & Grounded Answer]
   ├── Result Validator: Kiểm tra cột, kiểu số, chia cho 0 (ratio=null), watermark partial data
   ├── Answer Generator: Sinh câu trả lời bám sát số liệu cột/dòng (deterministic template / LLM)
   ├── Answer Validator: Đối chiếu từng claim số liệu, chặn suy diễn nguyên nhân, tự động fallback
   └── Final Response: Định dạng query.response.v1 (ready, needs_clarification, unsupported, forbidden, no_data)
```

## 3. Các Ranh Giới Bất Biến (Non-Negotiable Invariants)

Theo `scope.md` và `contracts.md`:
1. **Source of Truth duy nhất của Metric**: Mọi `metric_id` bắt buộc phải có trong `MetricCatalog` và ở trạng thái `status: "approved"` kèm `verified_handler: true`.
2. **LLM không được tự ý sinh hay thực thi SQL trực tiếp**: LLM chỉ tham gia trích xuất metric và gợi ý draft. SQL bắt buộc phải được biên dịch xác định (deterministic) bởi `SQL Compiler` từ `ValidatedPlan`.
3. **Database Read-Only**: Kết nối tới `cfo_warehouse.duckdb` luôn luôn mở ở chế độ `read_only=True`. Mọi hành động `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `COPY`, `ATTACH` đều bị triệt tiêu từ cổng an toàn (Safety Gate) đến tầng Database Engine.
4. **Nguyên tắc Fail-Closed**:
   - Nếu câu hỏi mơ hồ hoặc thiếu kỳ kế toán $\rightarrow$ hỏi lại (`needs_clarification`).
   - Nếu ngoài danh mục hoặc ngoài quyền hạn $\rightarrow$ từ chối an toàn (`unsupported` hoặc `forbidden`).
   - Tuyệt đối không tự suy đoán để chạy query liều lĩnh.
5. **Grounded Answer — Không bịa đặt số liệu**: Mọi con số trong câu trả lời bắt buộc phải có nguồn gốc dòng/cột (`source_columns`, `source_rows`) từ `ExecutionResult`. Không tự suy diễn nguyên nhân kinh doanh nếu dữ liệu truy vấn không thể hiện.
6. **Không rò rỉ dữ liệu nhạy cảm**: Public error và log observability tuyệt đối không chứa raw SQL, stack trace, credential hay các dòng dữ liệu tài chính thô.

## 5. Kế Hoạch Triển Khai Xây Dựng Mã Nguồn V0

Bạn có thể tự do dọn dẹp, tái cấu trúc hoặc thay thế các file code cũ trong thư mục `agent4/` (chẳng hạn các file chưa khớp contract) để dựng lại kiến trúc mới theo cấu trúc chuẩn module hóa sau:

### 5.1. Cấu trúc thư mục mã nguồn đề xuất cho `agent4/`

```text
agent4/
├── core/
│   ├── config.py             # Cấu hình runtime, database path, model endpoint, timeouts
│   ├── errors.py             # ContractError và mã lỗi chuẩn mục 1.3 contracts.md
│   ├── context.py            # NormalizedQuery, AuthContext, RuntimeContext
│   └── catalog.py            # MetricCatalog (Metric definitions, capabilities, approval check)
│
├── metric_selection/
│   ├── dense.py              # Dense vector retriever (sử dụng embedding model)
│   ├── lexical.py            # BM25 / token matching trên alias & label
│   ├── fusion.py             # Reciprocal Rank Fusion (RRF) & deduplication
│   ├── rerank.py             # Metadata reranker (view, locale, alias match)
│   ├── fewshot.py            # Dynamic few-shot bank & compatible_only selector
│   ├── llm_selector.py       # Tích hợp model cục bộ (Qwen 4B qua Ollama/vLLM/OpenAI-compatible)
│   └── validator.py          # Metrics Validation gate (subset check, view permissions)
│
├── planning/
│   ├── planner.py            # Phân tích slot (time, dimensions, filters, view, operation)
│   └── validator.py          # Semantic Plan Validation (allowlist, max_days, as_of vs range)
│
├── sql/
│   ├── compiler.py           # Biên dịch ValidatedPlan -> BoundQuery (parameterized, row cap)
│   ├── safety.py             # SQL Safety Validator (chặn DML/DDL, AST check, relation check)
│   └── executor.py           # DuckDB read-only connection pool, timeout, data watermark extraction
│
├── answer/
│   ├── result_validator.py   # Kiểm tra schema kết quả, NaN/Infinity, partial data watermark
│   ├── generator.py          # Grounded Answer generation (Deterministic templates / LLM prompt)
│   └── validator.py          # Answer claim verifier, chặn số ảo & suy diễn, fallback an toàn
│
├── pipeline.py               # Orchestrator kết nối toàn bộ 9 bước thành 1 hàm xử lý thống nhất
└── api.py                    # FastAPI endpoint tiếp nhận request và trả về query.response.v1
```

## 6. Tiêu Chí Hoàn Thành V0 (Definition of Done)

Một phiên bản V0 được nghiệm thu khi đáp ứng đầy đủ 5 tiêu chí:
1. **Pass toàn bộ Unit & Contract Tests**: Chạy lệnh kiểm thử `pytest tests/` đạt 100% (180/180 test cases pass).
2. **Pass Benchmark 120 câu hỏi**: Chạy `python scripts/evaluate_contract_benchmark.py` đạt tỷ lệ chính xác từ 95% trở lên trên dữ liệu `cfo_warehouse.duckdb`.
3. **Chống Prompt Injection & Unsafe SQL thành công**:
   - Chặn đứng 100% câu hỏi chứa prompt injection trực tiếp (`BM-115` – `BM-118`).
   - Xử lý an toàn, không rò rỉ dữ liệu từ sự kiện tiêm nhiễm ẩn trong database `A8_PROMPT_INJECTION` (`BM-119`, `BM-120`).
4. **Hoạt động trơn tru với mô hình cục bộ**: Module LLM Metric Selection gọi được model Qwen cục bộ trên máy và chuyển đổi mượt mà sang template/validator khi gặp sự cố mạng hoặc lỗi mô hình.
5. **Đầy đủ Provenance**: Mọi response hợp lệ đều trả đủ `catalog_hash`, `data_watermark`, `source` (`v_mgmt` / `v_tax` / ...) và `query_fingerprint`.
