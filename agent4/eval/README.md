Use the project virtual environment and UTF-8. Run from the repository root. The production CLI supports `--config eval/configs/Bstar.yaml`; without `--config` it retains the original P1 path.

The corpus and warehouse manifests are in `docs/5_handoff/measurements/`. Large generated data and raw model traces stay local in `data/` and `eval/results/`. TRAIN, val and test warehouse seeds are20251,71,9001. Financial labels come from the independent base-table oracle; E6 uses deterministic mutations of engine fixtures. Few-shot data comes only from TRAIN. See `docs/5_handoff/P2_PROTOCOL.md` for exclusions, sample sizes, scoring definitions and promotion rules.

Data preparation, in dependency order, for a new checkout with no existing frozen manifests:

```powershell
.venv/Scripts/python.exe -X utf8 -m eval.prepare_warehouses
.venv/Scripts/python.exe -X utf8 -m eval.gen.build_e1_e2
.venv/Scripts/python.exe -X utf8 -m eval.gen.build_behavior
.venv/Scripts/python.exe -X utf8 -m eval.gen.build_e6_e7
.venv/Scripts/python.exe -X utf8 -m eval.gen.build_e8_e10
.venv/Scripts/python.exe -X utf8 -m eval.gen.build_multi_why
```

Do not regenerate questions, labels or splits from model failures. Generators refuse to overwrite frozen manifests. Do not inspect generated test questions or per-case results before the final run. Aggregate hashes and reconciliation gaps are permitted preparation checks.

Start the dedicated Ollama server with `scripts/start_p2_ollama.ps1`; verify health before measuring. Profile: KV q8_0, Flash Attention, one parallel request, one loaded model, no cloud, RAM prompt cache disabled. Active-slot prefix reuse remains enabled. The default desktop server11434 is separate. Live-model tests run between measured arms. Machine/profile evidence is in `measurements/p2_runtime_profile.json`.

For the interactive CLI with that server, set `AGENT4_LLM_BASE_URL=http://127.0.0.1:11435` and `AGENT4_LLM_TEMPERATURE=0` before starting Python. The evaluation runner fixes temperature0 explicitly and records seed0/top_k20/top_p0.8, independently of shell defaults.

Example non-held-out run:

```powershell
.venv/Scripts/python.exe -X utf8 -m eval.run --split val --suite e1,e2,e5,e6,e8 --config B0 --out eval/results/new_val_run
```

`summary.json` records model/config/source/data hashes, successful-call token counts, unknown-usage calls, per-suite CI, exclusions, latency and server context-shift events. `results.jsonl` keeps raw public traces and oracle scoring; no SQL is supplied to the LLM. `gpu.json` samples total-device memory, including display and unrelated processes. This is not an allocator peak. Empty weight preload is timed separately; case latency includes first prompt prefill and failed/clarification responses. A fast refusal is not a correct financial answer.

The ordered experiment helper is `scripts/run_p2_experiments.py --stage <B0|H2|H1|H3|H4|H7|H8|H5|H6|H13>`. Complete and inspect both B0 source runs before the B0 stage. Each stage writes config/evidence/decisions, runs the full test suite, commits and publishes through `scripts/publish_card.py`. Results from identical configurations may be reused with explicit source-run provenance; this does not create a fresh latency sample. The helper never opens held-out test.

Finalization is deliberately separate: full B* val confirmation, immutable config/model/source/data freeze, then exactly one held-out run. `scripts/finalize_p2.py` implements these steps. The final runner checks an exclusive global claim, journals each started case before execution, and only resumes the same contract without repeating completed or lost-started cases. A published `eval/configs/test_consumed.json` receipt prevents a fresh checkout from silently repeating this test cycle. Once consumed, inspect the M2 report; do not run test again.
