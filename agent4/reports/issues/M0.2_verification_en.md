# M0.2 Verification Evidence

Date: 2026-11-06  
Issue: `docs/issues/M0.2_metric_catalog.md`  
Scope: M0.2 only; M1 and all later Issues were not implemented.

## Changes and acceptance evidence

- Added the production `MetricCatalog` with exactly 15 definitions from the
  module plan: 13 approved/verified metrics, one draft metric, and one metric
  whose handler is not verified.
- The catalog deep-copies constructor input; `get()`, `get_capability()`, and
  `list_visible_metrics()` do not expose mutable internal state.
- `get_capability()` returns `ContractError(code="unknown_metric",
  stage="metric_catalog")` for an unknown metric.
- Visibility requires `status == "approved"`, `verified_handler is True`,
  membership in `allowed_metrics` when restricted, and compatibility with at
  least one `allowed_view`.
- `catalog_hash` covers every definition, is stable for identical input, and
  changes when either metadata or a SQL expression changes.
- All four catalog tests import and instantiate production code from
  `agent4.core.catalog`; catalog behavior is no longer tested through
  `tests.contract_harness`.
- The 15 production definitions were compared with the existing reference
  definitions; both the count and complete dictionary structures match.

## Evaluation, limitations, and human review

explicitly does not require one. Model/prompt baselines, latency, and cost are
not applicable.

No known acceptance failure remains within M0.2 scope. The repository still
contains `agent4/engine/metrics.py`, a legacy 66-metric layer with a different
