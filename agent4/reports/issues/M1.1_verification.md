## Evaluation and review limits

- Recall@K, complete gold set recall, MRR, selection exact match, latency, and cost for E1/E2 were not measured. The referenced E0 summary at `reports/eval/M1_E0_full_catalog/summary.json` is absent from this checkout. Evaluator unit tests exercise the runner only.
- The evaluator uses `--config` for run metadata. The online adapters read runtime settings from `AGENT4_METRIC_SELECTION_CONFIG` or the checked-in default. A future experiment should use the same YAML for both, with a prebuilt matching index and candidate limits that allow K=15.
- Dense-only preserves dense order. Hybrid can expand authorized directed relationships before metadata reranking. An unmatched lexical query can yield an empty result. Dense Top-K can still return ranked candidates for such a query, leaving the final decision to the selector and validator.
- Requested-view compatibility uses explicit server context. The current evaluator input supplies reference date and timezone, so its reranker view component is neutral. Review of retrieval quality and the live provider path remains part of G2.
