# M0.1 Verification Evidence

Date: 2026-11-06

Scope: M0.1 only; M0.2 metric catalog remains in `tests.contract_harness`.

## Acceptance evidence

- Exact-key validation rejects unknown and missing fields at intake boundaries.
- `ContractError` sanitizes its exception string and public dictionary; SQL,
  tracebacks, credentials, and raw-row detail keys are not exposed.
- Query intake supports `v1`, `vi-VN` and `en-US`, enforces the 500-character
  limit, normalizes the question, and preserves/deep-copies caller input.
- Auth fails closed for absent, missing, empty, or invalid claims/policy values.
- Auth and runtime permissions come only from IdP/server-owned context; request
  body claims are ignored.
- Policy hashes are deterministic across permission ordering and distinguish
  unrestricted (`null`) from deny-all (`[]`) metric policy.
- `AppConfig` contains the paths, Qwen endpoint/model, question limit, row cap,
  and timeout required by the module plan.
