## Configuration and open gates

- The issue's documented `eval_adapter:predict` now routes to `predict_e5`. Use the named `predict_e0` to rerun E0. E5 reads the selected YAML via `AGENT4_METRIC_SELECTION_CONFIG`. Use the same YAML with the runner's `--config`.
- `llm.max_retries: 1` permits one model format retry. The independent opt-in recovery flags are `enable_empty_candidate_fallback`, `degraded_lexical_fallback`, and `enable_candidate_expansion`. The first action used consumes the request's recovery budget even when other flags are set. Degraded mode uses lexical retrieval and preserves the unavailable status if it finds no candidates.
- Live Ollama and E5 were outside the offline scope. There is no measured E5 invalid metric rate, recovery rate, latency, token usage, or selection accuracy by category. The two historical retrieval artifacts do not supply comparable selection baselines. G4 and the winning `config/selection.yaml` decision remain open. The existing YAML remains the baseline configuration.
